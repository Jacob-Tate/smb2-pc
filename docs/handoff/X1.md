# X1: integer divide-by-zero crash (0xC0000094) in Mode Select

Status: DONE (x64 only, D-9).

## Repro
`1350:START,1450:START,1550:START,1800:A,2300:A,2400:RIGHT,2420:RIGHT`, no pad, `--exit-frame 3000`
(with `SDL_GAMECONTROLLER_IGNORE_DEVICES`/`SDL_JOYSTICK_IGNORE_DEVICES=0x28DE/0x1304`). Crashes every time,
with and without `--det-session` (first RIGHT after the A at frame 2300; ~frame 2400).

## Locating it (method)
The port has a crash filter (`shim_crash_filter`, src/game/shim/stubs_manual.c) that prints the fault address.
The exe is PE with DWARF, ImageBase 0x10000000, so addresses are absolute:
`llvm-addr2line -f -i -C -e build64/bin/smb2_pc_port.exe 0x<addr>` and
`llvm-objdump -d -l --start-address=.. --stop-address=.. build64/bin/smb2_pc_port.exe`
(llvm-mingw `bin/`, run in WSL). Fault: `idivw %cx` with cx = 0 in `fn_3_32E0` (decomp sel_ngc.c:1086,
the Mode Select cursor handler; sel_ngc.c ~1163-1164 `*cursor % var_r6`).

## Root cause
Choosing Story Mode switches to menu screen 0x0C (`menu_start_story_mode`: `{0xFF, 255 /*entry_count*/, NULL entries,
bitflag 0x100}`), a transition screen with no entries that stays up while the mode loads. Its bitflag has no 0x4, so
menu_tick still calls `fn_3_32E0(1)`; with `lbl_3_bss_58.unk0 == -1` it uses `entry_count` = -1, so the modulus
`(s8)entry_count + 1` is 0. Pressing LEFT/RIGHT there computes `cursor % 0`.
On the GameCube this is harmless and happens on real hardware: PPC `divw` by 0 does not trap, and MWCC compiles
`a % b` as `a - (a / b) * b`, which is `a` whatever the undefined quotient is. x86 `idiv` traps.
The decomp is matched code compiled for PC, so the divide itself is faithful.

## Fix
`src/game/shim/stubs_manual.c`: a vectored exception handler (`shim_div0_handler`, installed by
`shim_install_crash_handler`, x64 only) for 0xC0000094. It decodes the faulting `div/idiv` (F6/F7 /6 /7, prefixes, REX,
modrm/SIB/disp), stores quotient = 0 (-1 for a negative signed dividend, the hardware value) and remainder = dividend,
skips the instruction and continues. It logs the first 8 occurrences as `[ppc-div0] ...`. An instruction it cannot decode
falls through to the crash filter. Generic: covers any other PPC-undefined divide in the decomp, not only this one.

Determinism: the result is a pure function of the operands and equals what the GC computes for `%` (the case here;
the quotient case is the documented hardware behaviour of divw/divwu, which MWCC code could in principle observe, but
nothing known does). Same on every machine, so no replay/netplay divergence. Sim state elsewhere is unchanged.
Here the cursor on the entry-less screen is left unchanged (`1 % 0 = 1`), exactly as on the GC.

Alternative (not done, decomp is read-only for this task): guard in the decomp under `#ifndef __MWERKS__`
(`if (var_r6 == 0) skip`) or add bitflag 0x4 handling; the handler makes that unnecessary.

## Verification
boot_to_menu, party_race_2p, record_replay all PASS; the repro script runs to --exit-frame 3000 (rc 0) with and without --det-session, logging one `[ppc-div0]` line.
