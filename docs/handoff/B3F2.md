  (`src/platform/platform_sdl2.c`), `--help` (`src/main/main.c`), `installer/smb2.nsi` (welcome, disc page,

## F2: build id
- `cmake/build_id.cmake` (run by custom target `smb2_build_id_gen` on every build) writes
  `<build>/gen/build_id_gen.h` and `build_id.txt` with copy_if_different. Id = `<git rev-list --count HEAD>-<sha7>[+dirty]`
  (tracked-file changes only); no git: `<UTC yyyymmddHHMM>-nogit`. Tries `git`, then `git.exe`: in a WSL build of a
  Windows-created worktree, WSL git can't read the worktree's `.git` file (Windows path), git.exe can.
- `src/platform/build_id.c` (lib `smb2_buildid`) is the only TU that includes the generated header; API in
  `include/build_id.h`: `smb2_build_id()`, `smb2_build_number()`, `smb2_build_sha()`. New commit -> only that TU + link.
- Used in: window title `Super Monkey Ball 2 – build N (sha)` (logged as `[window] title:`), first log line,
  `--version`, F1 overlay version (`v<ver>  build <id>`), `pc_session_default_config` build_id.
- Session/protocol: SessionConfig/protocol buildId are 40 bytes NUL-padded; the full id (<= ~24 chars) is stored as is,
  no hashing. Peers with different commits get the "build id" mismatch. Note: dirty trees all share "+dirty", so
  two different dirty builds at the same commit can't be told apart by the id (acceptable for dev).
- Friend package: folder/id = `build64/gen/build_id.txt` with '+' -> '_', padded/cut to 16 (`57-ebf7a7e______`).
  Dirty id = `<count>-<sha>d<archive hash>` (16 chars) so every different dirty package unpacks fresh.
  `SMB2_BUILD_ID` env still overrides.
