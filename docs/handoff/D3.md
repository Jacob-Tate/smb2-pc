# D3: Overlay input + gamepad navigation (done, x64 only)

## What changed
- `src/overlay/overlay.cpp`, `include/overlay.h`: `ImGuiConfigFlags_NavEnableGamepad` + `ImGui_ImplSDL3_GamepadMode_AutoAll` (any pad navigates);
  open/close = F2 (F1 stays the old overlay until D5), Guide button, or chord Back+Start held 0.5 s (`overlay_poll_tick`, called at the
  end of `sdl2_poll_events`); cursor shown while open, hidden after 3 s without mouse activity otherwise; window focused on open so
  gamepad nav starts; gamepad add/remove events reach ImGui even while closed. New API: `overlay_poll_tick()`, `overlay_input_blocked()`.
  Open/close logs `[overlay] open|closed (swapped frame N)`.
- `src/input/input_sdl2.c`: gate at the E3 pad hook (`if (game)` in the poll, before `loc[]`/`inputsync_exchange`, so record/netplay
  see neutral local pads; replay is untouched because it overwrites after the exchange). Local ports read neutral (buttons, sticks,
  triggers, analog A/B, Esc) while `overlay_input_blocked()` (open, or Back+Start currently both held so the chord's Start never leaks)
  and afterwards until all local buttons were released (latch). `err` is not touched. Log: `[overlay] local pad input gated (buttons 0x.. dropped) at poll N`.
- `src/game/shim/pc_overlay_pause.c` + hook in `video_shim.c` `video_finish_frame` (after the event poll, before the old F1 overlay):
  offline (`!netplay_active()`) and open -> `pc_overlay_pause_run()` re-presents the captured frame (the renderer draws the overlay on top) and
  pumps events until closed. No game pad poll runs meanwhile, so sim, input script and inputsync poll counter stand still. Works in
  record/replay sessions too. Logs `[overlay] game paused at poll N` / `game resumed at poll N (K frames presented while paused)`.
- `src/netplay/netplay_active.{c,h}`: **STUB for E6** (`int netplay_active(void)` returns 0). E6: replace `src/netplay/netplay_active.c`
  (keep the header; also keep or drop `netplay_test_force_active`) and the line in CMakeLists.txt. Online = never pause, still neutral input.
- `src/main/main.c`: test flag `--overlay-test-online` (forces `netplay_active()` to 1).

## Gotchas
- `--overlay-open-frames a-b` counts *swapped* frames, which keep advancing while paused, so a paused window ends after b-a presented frames.
- The script frame counter (`--input-script`) is the game-poll count; it does not advance while paused. To test the chord/gating with
  a script, use `--overlay-test-online` so the game keeps polling.
- Virtual pad buttons in scripts are SDL3 gamepad indices: `VB4` = Back, `VB5` = Guide, `VB6` = Start, `VB0` = A.
- The old F1 overlay and the new one can both be requested; unspecified interplay until D5 removes F1.
- Pad poll of the frame in which the overlay opens happened before the open (event order), except chord/Guide: Back+Start is
  detected from SDL state at the sampling point, so no leak. F2 open: that single poll is not gated (keyboard keys bound to the game, as the old F1).

## Human check (gamepad navigation in ImGui)
1. Run the exe normally with a controller attached, reach the title screen.
2. Hold Back/Select + Start for 0.5 s: the overlay opens and the game freezes (3D frame dimmed behind it). Guide/Home also toggles.
3. D-pad / left stick moves focus between widgets, A activates (checkbox toggles, button presses), B backs out, LB/RB tab-switch/ctrl-tweak sliders (hold X to tweak with the d-pad).
4. The game must not react to any of it (no menu movement/pause behind the overlay). Cursor visible while open.
5. Close with the chord again: the game resumes exactly where it was and does not see the Start press (no pause menu).
6. Mouse: cursor disappears 3 s after you stop moving it while the overlay is closed, reappears on movement.
7. Try a second controller: it can navigate too. F2 on keyboard works as before.
