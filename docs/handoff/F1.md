# F1 handoff: friend build (single self-extracting SMB2.exe)

Branch task/F1. Files: `platforms/windows/launcher/{launcher.cpp,launcher.rc,build.sh}`, `tools/package_friends.sh`,
`src/platform/install_mode.c` (small game change).

## Run
`MSYS_NO_PATHCONV=1 wsl -d Ubuntu -- bash /mnt/c/<worktree>/tools/package_friends.sh [--no-build]`
-> `build/package/friends/SMB2.exe` (~5 MB) + `README.txt`. The script builds the x64 release game (unless
`--no-build`), the launcher, archives `build64/bin` (no pdb/.debug/disc/.dat/.ini), zstd -19 compresses it.

## Decisions
- Compression: zstd (CLI in WSL; launcher decodes with the already-vendored `third_party/zstd/zstddeclib.c`).
  LZMS would need a Windows-side helper; zstd works on both sides with no new DLL. Imports of SMB2.exe: only
  system DLLs (KERNEL32, USER32, SHELL32, ole32, api-ms-win-crt-*).
- Build id: `build_id()` in package_friends.sh = first 16 hex of sha256 of the archive; `SMB2_BUILD_ID` env
  overrides (exactly 16 chars). F2: set that env (or edit the function). The launcher only reads the 16 chars
  from the trailer; it has no knowledge of how it was made.
- Save dir question: in portable mode (no install.ini next to the exe, which is the unpacked case) only
  settings.dat (and d3d12 shader cache) followed `--save-dir`; the memory card went to `<exe dir>\memcard` and
  logs were installed-mode only. Fix (install_mode.c): `pc_install_init` now sets the userdata base from
  `--save-dir` also in portable mode, so `card_shim.c` (`pc_userdata_base()`) puts `memcard\` there and
  `pc_install_setup_logs()` writes `logs\` there (console runs only, as before). Side effect: portable runs with
  `--save-dir` (tests) now keep the memcard there too, which is what the docs intended. Alternative rejected:
  writing an install.ini into the unpack dir (would enable installed-mode updater/gamedata logic).
- Launcher honors env `LOCALAPPDATA`/`APPDATA` (known folders only as fallback), so tests redirect everything.
  `SMB2_LAUNCHER_ASSUME_YES=1`: uninstall without dialog, no error dialogs. Launcher logs `[launcher] ...` lines
  to stdout when it is redirected, and passes std handles to the game.
- Launcher is a GUI-subsystem exe (no console flash). Uninstall deletes exactly `%LOCALAPPDATA%\SMB2\builds` and
  `%APPDATA%\SMB2\friend` (links are not followed); empty parents `SMB2` are left.
