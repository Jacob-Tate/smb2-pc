# E6: Netplay client (lockstep, ENet)

Status: client + acceptance script working on x64 (local Windows server). See "Verified" for what was run.

## What exists
- `src/netplay/netplay.{c,h}`: ENet client. `netplay_lobby_run()` (blocking command-line lobby, runs in `main()` before the
  session starts), `netplay_begin()` (after `pc_session_begin`: installs the `inputsync` NETPLAY callback + SDL event watch),
  `int netplay_active(void)` (real one; D3 adds a stub with the same signature, resolve at merge), `netplay_shutdown()` (atexit).
- `third_party/enet/` ENet 1.3.18 (unmodified, MIT) built as `smb2_enet` static lib; `ws2_32 winmm` linked (CMakeLists.txt).
- `src/netplay/inputsync.c`: `--record` now keeps recording the exchanged bundle (all 4 ports) while NETPLAY runs
  (set_netplay accepts RECORD -> NETPLAY and the NETPLAY case appends `out[]`). The recording replays with `--replay`.
- `src/main/main.c` flags: `--server host[:port]`, `--create`, `--join CODE`, `--name N`, `--delay N` (host; default 2),
  plus test flags `--players N` (host sends START_GAME when N members are in; default 2), `--room-code-file F` (host writes the
  code), `--lobby-timeout S` (default 120). `--server` implies the det session (config from GAME_START); with `--replay` it is an error.
  `--record`, `--checksum-log`, `--max-frames`, `--input-script` work as offline.
- `tools/netplay/two_instances.sh` (acceptance), `tools/netplay/build_server_win.sh` (Windows server exe from WSL).

## Behaviour
- Lobby: connect -> HELLO (build id from `smb2_build_id()`, disc hash 0 (see gotchas), locale 0) -> CREATE/JOIN ->
  host START_GAME(delay) when `--players` are in -> GAME_START -> `SessionConfig` (epoch from the server).
- Per poll `P` (index = `inputsync_poll_count`, same as the wire): first call sends neutral INPUT for polls 0..D-1; then each
  poll sends CHECKSUM if E3's `checksum_latest()` is new (every 60), sends INPUT for `P+D` (local pad 0 -> first owned port,
  pad 1 -> second, ...), then blocks until FRAME `P` (ring of 128, frames of another `gameSeq` / old polls dropped).
  Ports not in the FRAME `humanMask` read neutral with `err = -1` (no controller); E9 decides whether that stays.
- While blocked: `net_service(1)`, `platform_poll_events()`, `g_shim_frame_pulse++` (watchdog). Window close -> leaves (exit 0).
  Every second: log `[netplay] poll N: waiting for <name(s)> (x.ys)` (from the server's WAITING mask) and put it in the window
  title (restored afterwards). 30 s without the frame -> exit 3.
- SDL event watch (`SDL_AddEventWatch`, main thread only, throttled to 5 ms) services ENet and bumps the pulse while the OS
  modal move/size loop runs (no frames then). **Not tested interactively** (needs a human dragging the window).
- Ends: GAME_ENDED(host/last left) -> exit 0, desync -> exit 4, lost server -> exit 3 (E9 will turn these into "back to lobby").
- PERF every 60 polls (polls/slow>25 ms/stalls>10 ms wait/worst interval). NET_STATS ignored (E7 can use it).
- Peer timeout 10 s/30 s (ENet), so a stall of the main thread longer than that drops us (watch covers modal loops).

- Manual: host `smb2_pc_port.exe --iso ... --save-dir D --audio-null --server H:P --create --name A --players 2 --room-code-file code.txt --record a.bin --checksum-log a.txt --input-script S`,
  guest the same with `--join CODE --name B`. Replay: `--replay a.bin --checksum-log r.txt`.

## Gotchas
- ENet's win32.h pulls winsock2.h: in netplay.c include it before windows.h users; `s_host` clashes with a mingw macro (`inaddr.h`), so the variable is `s_enet`.
- The disc hash in HELLO is still 0 (E8 should send the real `fst_crc32` and put it into the session defaults); the server only requires it to match.
- Both instances boot at different speeds: the faster one sits in the first poll until the other joins lockstep (up to 30 s timeout).
- The server prints `held the game up` for slow-starting instances; harmless.
