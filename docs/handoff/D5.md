# D5: Replace old F1 overlay; FPS counter + toasts (done, x64 only)

## What changed
- **Old modal F1 overlay removed**: `pc_settings_overlay_run` / `overlay_draw` / `pad_held` deleted from `src/game/shim/pc_settings_menu.c`
  (the Options > Game Screen page stays), `pc_settings_overlay_request/take_request` deleted from `pc_settings.{c,h}`, the F1 case from
  `platform_sdl2.c`, the old-overlay run in `video_shim.c`. The input-script token `F1` now calls `overlay_toggle()` (new overlay).
  The Controller sticks / Updates / Memory card screens are untouched (they have their own requests; the new overlay's rows still trigger them).
- **F1 opens the new overlay** (`overlay_process_event`). **F2 stays as an alias** (harmless; D3 tests used it). Guide button and the Back+Start
  chord (0.5 s) as before. Footer hint and Close help text say F1.
- **FPS counter**: drawn at the `g_pcs.show_fps` corner (1 TL, 2 TR, 3 BL, 4 BR), with or without the menu open, GL + D3D12. Value = `io.Framerate`
  (ImGui's average of presented frames). Partyboard look: #253b9c panel, #009dda border.
- **Toasts**: `overlay_toast(type, title, body)` in `include/overlay.h`; types `OVERLAY_TOAST_INFO/SUCCESS/WARNING/ERROR`. Top right (below the FPS box
  when that is TR), stacked oldest-on-top, max 5 (oldest dropped), duration 4 s + 30 ms per body char, 0.2 s fade in / 0.4 s fade out + small slide,
  upper-case coloured heading. Main thread only; no-op before `overlay_init`; also logs `[overlay] toast (type): title - body`.
  Used now by controller hot-plug (`input_sdl2.c`: "Controller connected / disconnected" + name + player number; not for the pads present at start-up).
  **E7/E9**: just call `overlay_toast`.
- **Rendering whenever something is visible**: new `overlay_wants_draw()` (open, or FPS corner set, or a toast alive). Both renderers use it where
  they used `overlay_is_open()` (GL `glb_draw_overlay`, D3D12 present + frame-dump compose). When nothing is visible no ImGui frame is built
  (zero cost; `overlay_render` only runs the test schedule hook). While the menu is closed the SDL backend's cursor control is switched off
  (`NoMouseCursorChange`) so the 3 s idle cursor hide from D3 keeps working.
- Test hook `--overlay-test-toast FRAME:type:Title:Body` (main.c, `overlay_test_toast`). `docs/testing.md` documents it, `--overlay-test-set`,
  `--overlay-test-online`, the chord via `VB4/VB6`, and hot-plug toasts via `VADDX/VDEL`. README controls updated.
- Screenshots (2x downscaled) in `docs/handoff/D5/`: FPS+toast with the menu closed (GL, D3D12), menu open + FPS + toast (GL, D3D12),
  hot-plug connect/disconnect stack with FPS bottom-left (GL, D3D12), chord open (GL), F1-token open (D3D12).

## Gotchas
- The frame dump of the open menu while paused shows a low FPS (frames are re-presented unthrottled / dump cost); not a bug.
- Toast duration is wall-clock (SDL ticks), not frames; scripted tests dump within ~5 s of the event.
- A real keyboard F1 press cannot be injected headless; the key path is a 1-line check in `overlay_process_event`; the script `F1` token and the
  chord / Guide were driven instead.

## Commands (Git Bash, x64; cd into an empty dir first, frame dumps go to the cwd)
    export SDL_GAMECONTROLLER_IGNORE_DEVICES=0x28DE/0x1304 SDL_JOYSTICK_IGNORE_DEVICES=0x28DE/0x1304
    E="smb2_pc_port.exe --iso <iso> --save-dir <tmp> --windowed --audio-null --renderer gl|d3d12"
    # FPS counter + toast with the menu closed
    $E --overlay-test-set show_fps=2 --overlay-test-toast "290:warning:Test toast:Hello" --dump-ranges 300-301 --exit-frame 302
    # hot-plug toasts, FPS bottom-left
    $E --input-script "100:VADDX,300:VDEL" --overlay-test-set show_fps=3 --dump-ranges 330-331 --exit-frame 335
    # chord opens the menu (online mode: no pause)    /    F1 token opens it (offline pause)
    $E --overlay-test-online --input-script "100:VADDX,200-270:VB4,200-270:VB6" --dump-ranges 300-301 --exit-frame 302
    $E --input-script "100:F1" --dump-ranges 300-301 --exit-frame 302
