# B2 handoff: RVZ decoder (includes B4 verification)

Status: DONE (branch task/B2).

## What exists
- `src/assets/rvz.{c,h}`: native GameCube RVZ reader (`rvz_open/rvz_read/rvz_size/rvz_close`), plugged into
  `disc_reader.c` as format "rvz" (chosen by `RVZ\x01` magic). `iso_open`, `gamedata.c` etc. need no change.
- `third_party/zstd/` zstd 1.5.7 `zstddeclib.c` (generated with `build/single_file_libs/combine.py -r lib
  -x legacy/zstd_legacy.h zstddeclib-in.c`) + `LICENSE`; CMake static lib `smb2_zstd` (compiled with -w). No new DLLs.
  Credits added to README and `installer/LICENSE.txt`.
- Hidden CLI: `smb2_pc_port.exe --rvz-dump <in.rvz|iso> <out.iso>` decodes a whole image and prints time and MB/s.

## Format notes (what was implemented)
- Header 1 at 0 (0x48 bytes): iso_file_size at 0x24, rvz_file_size at 0x2C. Header 2 at 0x48 (0xDC bytes):
  disc_type, compression, level, chunk_size, dhead[0x80], n_part (0x90), n_raw (0xB4), raw_off (0xB8),
  raw_size (0xC0), n_groups (0xC4), group_off (0xC8), group_size (0xD0). SHA-1 hashes are not checked.
- Raw data and group tables are compressed with the disc's compression (zstd) or plain (none).
  Raw entry 24 bytes, group entry 12 bytes {off/4, size | 0x80000000 = compressed, rvz_packed_size}.
- First 0x80 bytes of the disc come from `dhead`. Raw entry start is rounded down to 0x8000 (size grows
  accordingly); group i covers chunk_size bytes of that rounded range (last one shorter).
- data_size low 31 bits == 0 -> all zero. Compressed flag clear -> stored as-is (even when disc compression is zstd).
  `rvz_packed_size != 0` -> after decompression the data is an RVZ-packed stream: u32 BE size (bit 31 = junk);
  junk run is followed by 68 seed bytes (17 BE words) and is generated by the lagged Fibonacci generator
  (buffer[i] = b[i-17]<<23 ^ b[i-16]>>9 ^ b[i-1] for i in 17..520, 4 forward steps, forward = xor with j=32 lag,
  output bytes = word>>24, >>18, >>8, >>0; advance by (group_start + bytes_already_output) % 0x8000 bytes at the
  start of EACH junk run, group_start counted from the (rounded) start of the raw entry).
- GC discs have no exception lists in raw data; they are not parsed (Wii partition data is rejected).
- Errors: Wii/other disc types, n_part != 0, bzip2/LZMA/LZMA2/Purge ("... not supported; re-convert in Dolphin with
  zstd"), header file size != real size (truncated), table/group outside file, zstd errors or size mismatch.
  Read-time errors print `[rvz] read error ...` once on stderr and make `disc_reader_read` return false.
- Cache: the last decoded group (chunk_size bytes) is kept; sequential reads hit it.

## Results (2026-11-17)
- Full decode of `Super Monkey Ball 2 (USA).rvz` (646,679,824 bytes) -> 1,459,978,240 bytes, SHA-256
  identical to the real ISO (b3e40531...571315), x64 2.02 s (690 MB/s), i686 2.12 s (656 MB/s).
- `--iso <rvz> --exit-frame 900` OK on both arches; `--extract-iso <rvz>` -> 3014 files, verify RESULT OK,
  manifest and whole extracted tree identical to extraction from the ISO.
- Truncated RVZ (first 10 MB): "RVZ file is truncated or corrupt (header says 646679824 bytes, file has 10485760)".

## Gotchas
- `main.c` and several others are CRLF; `.sh/.py/CMake` are LF.
- `--iso <bad.rvz>` shows the reader's message then falls back to the picker (pre-existing flow from B1).
- Bytes corrupted inside a compressed group are only detected if zstd notices (frame checksum not verified here
  unless present); the whole-file size check catches truncation.
