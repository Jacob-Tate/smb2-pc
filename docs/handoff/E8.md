# E8: Session start flow + sim-affecting settings sync

Status: IN PROGRESS (see "Left" at the bottom; this file is updated as work lands).

## Decision: restart the exe (relaunch), not an in-process reset
E1 D20 / E2: a session needs a FRESH process (audio synth state, rand state, card, quit flags, heap layout, watchdog, static
variables inside the decomp all start from their initial values on every peer).  The game has no "reboot" entry, so an
in-process reset would mean auditing every static in the decomp; a restart is the verified path (all E4 determinism runs are
fresh processes).  So, like partyboard's `relaunch`: on GAME_START each client restarts the exe and the new process
reconnects and takes its seat back.  Only the main loop of the new process differs from a normal boot (it first finishes the
online handshake, then `pc_session_reconfigure`s with the room's config and runs lockstep from poll 0).

## Flow (in-game lobby)
1. Offline game running.  The platform loop calls `netplay_lobby_tick()` once per `video_finish_frame` (and once per frame of the
   overlay pause loop, `pc_overlay_pause.c`).  API in `src/netplay/netplay.h` (connect / create / join / set_port / set_delay /
   start / leave / room / events).
2. Host `netplay_lobby_start()` -> server GAME_START to everyone.
3. Each client (`begin_relaunch`): sends `RELAUNCHING(token)`, spawns itself with
   `<original args minus lobby args> --server H:P --name N --np-resume CODE,ID,TOKEN --np-wait-pid <old pid>`,
   closes the connection politely (`enet_peer_disconnect_later`, so RELAUNCHING is acknowledged first) and asks the game to quit
   (`pc_quit_request`).
4. New process: waits for the old pid, resolves the game data, reconnects (HELLO), sends `RESUME(code,id,token)`; server
   rebinds the old seat (same client id), answers WELCOME, ROOM_STATE, GAME_START (same cfg/epoch/owners/seq).  The process then
   `pc_session_reconfigure(cfg)`s (it began a default session early so nothing touches disk), `netplay_begin()`, boots.
5. Session end (host END_GAME, last human left, desync, lost server): `session_end` restarts the exe into normal offline mode
   with `--np-notice "Online session ended: ..."` (toast), unless the run is automated (`--max-frames` / `--input-script`) or
   was started from the command line, which exit with codes 0/3/4 as in E6.  E9 will turn this into "back to the lobby".

## Server changes (protocol version unchanged = 1; additive)
- `SMB_MSG_RELAUNCHING = 11` (u32 token), `SMB_MSG_RESUME = 12` (code[4], u8 oldClientId, u32 token), WELCOME has a trailing
  capability byte (`SMB_CAP_RESUME`).
- A member that sent RELAUNCHING and then disconnects keeps its seat for `SMB_NET_RESUME_GRACE_MS` (90 s) instead of being
  dropped; lockstep simply waits for its input.  A plain disconnect is still a drop.  RESUME with a wrong token / unknown seat
  -> ERR_NO_SUCH_ROOM.  `tools/server_test.sh`: 90 checks pass (new `[resume]` scenario).
- **The deployed server (10.0.0.5:7855) runs the OLD build**: it knows neither message.  Against it the command-line path
  (`--server --create/--join`, no restart) still works; the in-game start refuses with a toast ("server too old", no
  `SMB_CAP_RESUME`).  Redeploy the server (E10 CI image) before using the in-game lobby for real.

## Command-line flags (kept)
`--server H:P --create|--join CODE --name N --delay N --players N --room-code-file F` = blocking wrapper over the same API
(`netplay_lobby_run`) in a fresh process, no restart.  Needs the game data first (disc hash), so it runs after
`platform_resolve_game_data`; the session begins early with defaults and `pc_session_reconfigure` swaps in the room's config.

## Disc hash / config
HELLO now carries `iso_fst_crc32()` (CRC-32 of the disc FST, equal to `fst_crc32` of a gamedata manifest) instead of 0.
The session config carries build id, disc hash, locale, epoch, flags; everything else E1 lists is forced canonical by E2 in any
session (see E2.md).  Locale: `netplay_lobby_set_locale()` (default 0); all members must announce the same (server compares at
JOIN), game forces `cfg.locale`.
