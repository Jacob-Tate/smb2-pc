# E7: Online lobby UI (overlay "Online" tab)

Status: DONE (x64, Windows). Human REVIEW needed for look + real keyboard/gamepad entry (see "Not tested").

## What exists
- `src/overlay/tab_online.cpp`: the tab. Views by lobby state:
  - disconnected: server address + name (text rows, remembered in settings.dat as `np_server` / `np_name`, default `NETPLAY_DEFAULT_SERVER` / "Player"), Connect.
  - connected: Host (Input delay row: Auto from pings or 2..12 frames, Create room), Join (Room code text row + 4 "Code letter" rows for gamepads, Join room), Disconnect.
  - in a room: big room code panel, Copy room code (clipboard), P1..P4 rows (name, [host], (you), ping; press a free port to take it), host: Input delay + Start game (needs 2+ players and a server with RESUME), guest: "waiting for the host", Leave room, Disconnect.
  - session running (`netplay_active()`): room, delay, players/ports/pings, Leave session (with Yes/No confirm; the leave is deferred to the next `online_tick`, then `netplay_session_leave()`).
  - status line (`netplay_lobby_status`) is the first row of every view.
- `online_tick()` (called from `overlay_poll_tick`, i.e. once per `platform_poll_events`, also while the overlay is closed or the game is paused): pumps `netplay_lobby_next_event` into `overlay_toast` (kind -> info/warning/error; title "Online" / "Online error"), runs the test script, performs the deferred session leave, and closes the overlay when the lobby reaches STARTING (an open overlay pauses the game loop, which would otherwise never quit for the restart; found by the test script).
- `src/overlay/overlay_ui.{h,cpp}`: new rows `text_row` (A / click / Enter edits in place with ImGui InputText: typing, Ctrl+V; Enter or Esc/B ends; `upper_code` filters to upper-case letters), `stepper_row`, `action_row`; `online_locked()`.
- D4 FOLLOW-UP done: while `online_locked()` (session running or lobby JOINING/IN_ROOM/STARTING/RESUMING) the Controller sticks (Input), Memory card, Updates screen and "Choose a different disc image" buttons are disabled, and Language shows "locked online" (Game tab).
- Title screen hint "F1 / Back+Start: Online" (small, bottom centre) in `overlay.cpp`: drawn when `main_mode == 0 && sub_mode == 8` (the "PRESS START" screen; found empirically, `SMD_ADV_*` names in the decomp list are offset), overlay closed, no session. It makes `overlay_wants_draw()` true on that screen.
- `src/platform/pc_settings.c`, `include/pc_settings.h`: `np_server`, `np_name`, `pcs_set_netplay()`; saved on Connect (not in a session; `pcs_save` is a no-op there).
- netplay.{c,h} (additive, small): `netplay_session_leave()`, `NetplayRoomInfo.in_game`, `netplay_lobby_room()` also answers while the session runs (`delay` = session delay), `--overlay-test-online-script` in the relaunch strip list.
- main.c: `--overlay-test-online-script` (same handling as `--lobby-test-script`: the offline process ignores `--record/--max-frames/--input-script`, the restarted session process gets them).

## Test hook: `--overlay-test-online-script "T:verb=arg,..."`
Calls the same `online_*()` functions the buttons call. T = tick (platform_poll_events calls). Verbs: `connect=HOST:PORT/NAME`, `host=DELAY`, `join=CODE|@FILE`, `codefile=FILE`, `port=P`, `start=N`, `leave`, `disconnect`, `leave_session`, `tab=NAME`, `open`, `close`, `wait=TICKS`, `players=N`, `dump=NAME` (requests a frame dump 4 swaps ahead, frame number is logged; `open`/`close` cancel `--overlay-open-frames`). Documented in docs/testing.md.

`tools/netplay/online_ui_instances.sh` (new; structure of lobby_instances.sh): host and guest set up the room through the tab actions, dump the tab in each state, start; the session processes dump the Online tab at frame 1100 (`--overlay-open-frames 1000-1120`); then checksums / recordings / replay are compared. `tools/netplay/ppm2png.py` converts the dumps (needs PIL; the script skips PNGs without it).

## Not tested / gotchas
- Typing with a real keyboard into the text rows, Ctrl+V paste, Copy room code, and the gamepad letter picker were not driven (no key injection in headless runs); the nav-focus hand-back after an edit (`s_refocus_id`) is untested. Needs a human.
- Leave session was not run end-to-end (it ends the process: `session_end` restarts into offline play, or exits in automated runs). E9 reworks session end; `netplay_session_leave` just calls `session_end(0, ...)` so it follows whatever E9 does.
- Room view is taller than the pane; Leave room / Disconnect are below the fold (scroll with the nav).
- The deployed server (10.0.0.5) is OLD: Start refuses with the "too old" toast until E10 redeploys.
- Name is not defaulted from the Windows user name (privacy); gamepad-only users keep "Player" unless they use a keyboard once.
- Tests start with `rm -rf` of their own SMOKE_OUT only; every instance uses a throwaway `--save-dir`.
