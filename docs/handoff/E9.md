# E9: Disconnects and desyncs

Status: see "Verified" at the bottom. x64 / Windows only (D-9).

## What happens now

### A player drops (kill, crash, Quit to Desktop, connection lost)
- The SERVER decides. Disconnect (ENet goodbye, or its 5-15 s timeout for a kill) -> `dropFromGame`: the port leaves
  `humanMask`; every FRAME from the next flushed poll carries the new mask (`SMB_FRAME_PORTS_CHANGED`) and PLAYER_DROPPED
  (informational). Frames are broadcast, so every client sees the mask change on the same poll (verified: both survivors log
  `poll 1502: human mask 07 -> 05`). The client trusts the per-FRAME mask only (E5/E6 behaviour, verified end to end).
- The game then sees on that port: all-zero pad with `err = -1` (no controller), same on every peer, same as a never-seated port.
  Decision per mode (E1 #11): `err` is only read by menus/option screens (`merge_inputs` skips `err == -1` pads;
  `option.c`/`sel_ngc_option.c` show "no controller"); in-game player control goes through `player_pad_map` and ignores
  `err`, so a vanished pad just stops steering (ball idle, boat/plane/club untouched). No mode needed `err = 0`; keeping
  `err = -1` also keeps "use all pads" menus from counting the dead pad. No game-side change.
- The session goes on while at least one human remains (server ends the game with `SMB_END_PLAYER_LEFT` only when the mask is 0).
- Toast (via the E8 event queue, `netplay_lobby_next_event`): `<name> left the game` (from PLAYER_DROPPED) plus a log line
  `P2 (Bob) is neutral from here on (no controller)` at the poll where the mask changes.
- **Pause menu "Quit to Desktop"** in a session: unchanged code path (`pc_quit_request` -> `pc_quit_poll` -> `exit(0)`), the
  `atexit(netplay_shutdown)` sends the ENet disconnect, so the server sees a clean leave = drop. Verified with the hook
  `SMB_NETPLAY_TEST_DROP=<poll>:quit` (calls `pc_quit_request` like the pause row does).
- If the host drops, the host role passes to the first remaining member (server, E5); the game goes on.

### Desync
- Checksums (E3, every 60 polls) are compared ONLY by the server (all humans must report the same poll). On mismatch: DESYNC,
  then GAME_ENDED(reason 2) + lobby ROOM_STATE to everybody, room kept in the lobby phase. There is no local detection (a
  client can't see the others' state); the clients' job is to end cleanly.
- Client: `check_end` -> `session_end(4, "the game ended: DESYNC (...)", room_alive=1)` -> error toast + back to the lobby.

### Host ends the game
- `netplay_end_game()` (new, host only, in a session) sends END_GAME (E5 message); everybody gets GAME_ENDED(reason 3) and
  goes back to the lobby like for a desync. E7 should call it from the overlay ("End game for everyone").
  Test hook: `SMB_NETPLAY_TEST_ENDGAME=<poll>` on the host.

### Back to the lobby (the E8 FOLLOW-UP) - design
A session is a separate, fresh process (E1 D20), so "back to the lobby" = restart again, reusing E8's seat-hold mechanism:
1. Session process gets GAME_ENDED (desync / host / last-left). The server already put the room in lobby phase; members stay.
2. It sends `RELAUNCHING(token)` (now accepted in the lobby phase), spawns itself as a normal OFFLINE game with
   `--server H:P --name N --np-resume CODE,ID,TOKEN --np-lobby --np-notice "Back in the lobby - <why>" --np-wait-pid <pid>`
   (session args like `--record --max-frames --checksum-log --input-script --det-session` are stripped, as for the offline restart),
   closes the connection with `enet_peer_disconnect_later` and exits. Shared code: `hand_over()` (also used by `begin_relaunch`).
3. Server: a disconnect of a member that sent RELAUNCHING keeps its seat (`away`) for `SMB_NET_RESUME_GRACE_MS` (90 s), in the
   lobby phase too (was: only in a game). Meanwhile START_GAME is refused with "waiting for X to come back to the room".
4. New process: `main.c` sees `--np-lobby` (the `--server` value is kept aside so it is NOT treated as a session), and after the
   game data is resolved calls `netplay_lobby_return()`: non-blocking connect, HELLO, `RESUME(code,id,token)`. The server rebinds
   the seat (same client id, same port, host role unchanged), answers WELCOME + ROOM_STATE (no GAME_START: room is in the lobby phase).
   `netplay_lobby_tick` then moves `NP_LOBBY_RESUMING -> NP_LOBBY_IN_ROOM` (log `[netplay] back in room XXXX (lobby): N player(s)`,
   toast "Back in room XXXX"). E7's UI just sees a normal offline game that is already connected and in a room; the
   notice ("Back in the lobby - the game ended: DESYNC (...)") is in the event queue. The host can START_GAME again.
5. If the server lacks the new cap (`SMB_CAP_LOBBY_RESUME`, WELCOME caps bit 2), the lobby phase can't hold the seat, or the
   restart fails: fall back to the E8 behaviour (restart offline with a notice, no room). Lost server / 30 s timeout = offline
   restart with a notice (room can't be kept: the game is still running there / we are gone).
6. Command-line (`--server --create/--join`) and automated runs (`--max-frames`, `--input-script`) still just exit with
   0 / 3 (lost server, timeout) / 4 (desync), unless the test flag `--np-lobby-return` is given.

Server/protocol changes (version unchanged = 1, wire layouts unchanged, additive): `SMB_CAP_LOBBY_RESUME = 2` in WELCOME's cap
byte, RELAUNCHING and RESUME accepted in the lobby phase (RESUME answers WELCOME + ROOM_STATE only when the room is not in a
game), disconnect of a RELAUNCHING member holds the seat in the lobby phase, START_GAME refused while a member is away/restarting.
**The deployed server (10.0.0.5) is an old build: it must be redeployed before the back-to-lobby path works; against an E8-era
server (RESUME but no LOBBY cap) the client falls back to "restart offline with a notice".** `tools/server_test.sh`: 106 checks pass
(new `[resume: back to the lobby after a game]` scenario).

### Watchdog / stalls (E4 T8)
- The lockstep wait (`net_exchange`) bumps `g_shim_frame_pulse` every loop iteration and pumps SDL events, so waiting clients are
  never killed by the 8 s hang watchdog (`stubs_manual.c`), however long they wait. After 30 s without a FRAME (90 s for the first 4
  polls) `session_end(3, "timed out waiting for the other players")`: message, disconnect (= the server drops us, the others go on),
  exit code 3 (or restart offline with a notice in an in-game-lobby session).
- A completely frozen process (real SIGSTOP) is a different case: ENet on the server gives up on it after ~5-15 s (server peer
  timeout 5 s/15 s) and it is dropped like any other disconnect.

## Test hooks (environment variables, read at `netplay_begin`, plain `getenv`; they only change what this client does)
| Variable | Effect |
|---|---|
| `SMB_NETPLAY_TEST_DROP=<poll>[:quit\|:leave]` | at that poll: hard kill (`TerminateProcess`, no goodbye) / `pc_quit_request` ("Quit to Desktop") / send LEAVE_ROOM and exit |
| `SMB_NETPLAY_TEST_DESYNC=<poll>` | every checksum report from that poll on is corrupted (the server then reports DESYNC) |
| `SMB_NETPLAY_TEST_STALL=<poll>:<ms>[:net]` | sleep in the main loop for that long at that poll; the hang-watchdog pulse is kept alive; with `:net` ENet is still serviced (connection stays up), without it the network is frozen |
| `SMB_NETPLAY_TEST_ENDGAME=<poll>` | host sends END_GAME at that poll |
Flags: `--np-lobby-return` (go back to the lobby even in automated runs), `--np-return-script SPEC` (the `--lobby-test-script`
of the process that returns to the lobby; new steps `F:report=FILE` writes room/players/host to FILE once in a room, `F:exit` exits).
