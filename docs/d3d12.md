# Renderers: GX core, OpenGL and Direct3D 12

The port has two GPU backends, OpenGL 3.3 core and Direct3D 12, behind one
backend-neutral emulation of the GameCube GX API.

## 1. Architecture

```
            game / shims (GX* calls)
                     |
   src/render/gx_core.c   backend-neutral GX emulation (section 2)
                     |    GxGpu interface: src/render/gx_gpu.h
                     |    (optional HFR proxy in between: gx_hfr.c, docs/hfr.md)
          +----------+-----------+
          |                      |
 render_opengl.c          render_d3d12.c
 (GL 3.3 core)            (D3D12 + DXGI flip model, HLSL)
```

* `gx_gpu.h` defines the backend interface (`GxGpu`): init/shutdown,
  resize, present, vsync, viewport/scissor (window pixels, GL bottom-left
  origin; the D3D12 backend flips), blend/depth/cull, clear (optional rect),
  texture create/update/wrap/LOD/destroy/bind, `draw` (vertices + optional
  quad UV rects + two constant blocks + depth-clamp/no-cull flags),
  `read_pixels`, `read_pixels_box` and `copy_tex` (EFB copies), frame
  capture/restore (F1 overlay), `read_frame` (frame dumps).
* The core builds the shader constants into two plain C structs laid out
  exactly like the HLSL cbuffers (every member 16-byte aligned, matrices in GL
  column-major order, which is also HLSL's default `column_major` packing):
  * `GxDrawConsts` (b0): matrices, texgen masks, mode flags, alpha compare,
    UI TEV colours, fog; changes per draw.
  * `GxTevConsts` (b1): channels, lights, TEV stages, konst/regs, indirect
    state, post-texgen matrices; changes rarely, versioned by a serial.
  The GL backend uploads the same values through a uniform cache.
* No shim uploads textures directly: every texture goes through
  `GXInitTexObj` (button_prompts.c binds decoded PNGs through the same path).

## 2. What the core emulates

* EFB (640x448/480) to window mapping with an aspect box; rects are mapped
  by rounding each edge, so adjacent rects tile exactly.
* Projection canonicalisation (`GXSetProjectionv` / `GXGetProjectionv`): GX
  reads only 6 elements + the type, so the matrix is rebuilt from those.
* Matrix banks, immediate-mode vertex batching (a batch is flushed on any
  state change because GXEnd is a no-op on GC), wide lines expanded to quads
  on the CPU (core GL has no wide lines), 2D quad UV clamp.
* GC texture decoding (I4/I8/IA4/IA8/565/5A3/RGBA8/CMPR) and the texture
  cache (section 5).
* GXFX lighting channels + N-stage TEV, GXIND indirect texturing, texgen
  sources, fog including the per-shape no-fog `fn_80066674`.
* `GXSetTexCopySrc/Dst` + `GXCopyTex` (section 4).
* The frame kickoff (`gx_start_new_frame`: present + EFB clear + z/alpha
  reset).

One GLSL / HLSL uber shader implements the vertex side (GX lighting
channels, texgens, GX clip-z remap: GX z/w is in [-1, 0]) and three pixel
modes: GXFX TEV (konst, regs, indirect, alpha compare, fog), UI TEV
(`tex*C0 + C1`, the 2D path) and plain `vertex color * tex0` (avdisp models).

## 3. Rules both backends follow

* Depth clamp (no near/far clip) only for ortho draws; perspective draws
  clip (clamping also removes near-plane clipping, which smears triangles
  that cross the camera plane).
* GX_CULL_FRONT/BACK map to GL with `glFrontFace(GL_CW)`; quads and expanded
  lines are never culled; `GX_CULL_ALL` culls every triangle (not points).
* Z compare off + update on still writes depth (compare = ALWAYS).
* Blend: `glBlendFuncSeparate(src, dst, ONE, ONE_MINUS_SRC_ALPHA)`, subtract =
  reverse subtract for colour and alpha.
* The frame clear ignores the scissor and paints black bars outside the aspect
  box; it obeys the current depth write mask (as glClear does).
* Copy-clear clears colour + depth of the copy rect regardless of masks.
* EFB copies return alpha 0xFF (the EFB is RGB8).
* Sampling an unbound unit returns (0,0,0,1) (GL incomplete texture).
* Default MSAA is 4x (settings.dat `msaa`, `--msaa`); reads resolve.
* Out-of-range GX enums (the game passes some: race2 calls `GXSetZMode`
  with func 74) behave like the GL switch defaults: depth func LEQUAL, blend
  src ONE / dst ZERO, unknown cull mode ignored.
* The default framebuffer is drawn y-up: edges exactly on pixel centres
  fill the visually-lower row.

## 4. EFB copies (`GXCopyTex`)

GC `GXCopyTex` converts an EFB rectangle into texels in main memory. The
core resamples the rectangle to the destination size, encodes it into the
real GC texel layout at `dest` (so CPU readers and the regular decoder
agree), and keeps a backend texture per destination address that
`GXInitTexObj` hands out while the memory still hashes the same.

* Colour copies in the formats with a GPU conversion (I4/I8/IA4/IA8/565/
  5A3/RGBA8 and the R/RA/RG/GB copy formats) never stall: `copy_tex`
  resolves the target, box-resamples the rect on the GPU (the exact integer
  mean of the CPU loop) into a dw x dh UINT target and, in the same pass,
  writes the texels the copy format reads back as straight into the game's
  texture. The raw result goes to a readback buffer (D3D12: per ticket,
  completes with the frame fence; GL: PBO + fence) and the core encodes it
  into GC memory a frame or so later (polled per frame, forced before
  anything needs the bytes, dropped if the game rewrote that memory).
* Other colour formats use `read_pixels_box` (same GPU resample, synchronous
  readback of dw x dh); depth copies use the full-size `read_pixels` + CPU
  resample.
* `SMB2_COPY_CPU_RESAMPLE=1` forces the CPU path, `=2` verifies the GPU
  paths against it (`[copyverify]` lines), `=3` disables the async path.

## 5. Texture lifetime

The game re-inits GXTexObjs constantly (sprites every frame), so backend
textures are cached in records keyed by identity (image pointer, size,
format, wrap modes, mip flag) and validated by a content key
(`texcache_key`: samples of the start, middle and end of the texel bytes, so
memory reused at the same address is not mistaken for the old texture).

On GC there is no texture object to free: a GXTexObj only points at texel
memory, which the GPU reads when it draws. A record is therefore retired
when its texels can no longer be what that memory holds:

* superseded: the same identity was re-inited with different content
  (memory rewritten in place: glyph pages, reused heap blocks);
* freed: the memory was freed (`OSFreeToHeap`) or a heap was created over it
  (`OSCreateHeap`, when game heaps are re-made on a mode change; not
  `OSDestroyHeap`, alloc.c keeps the blocks of a destroyed main heap);
  os_shim.c reports the range through `pc_tex_mem_freed_hook`;
* evicted: not bound for `TEX_EVICT_AGE` frames while the alive textures
  exceed the budget (`SMB2_TEX_BUDGET`, MB of RGBA8). This covers memory
  that changes without a free: buffers the game sub-allocates itself, or
  PC-side memory.

A GXTexObj holds the record id + generation, not a pointer. Binding one
whose record was retired (generation mismatch) re-inits it from its image
pointer and fields, like the GC reading the memory at draw time; the LOD
settings of the retired record are carried over. Retired textures are
destroyed at the next frame start, after the frame that may have used them
was submitted, and not while still bound in the core. The backends keep
the resource alive for the frames still in flight (D3D12 releases it after
the GPU fence and reuses the CPU SRV slot), and the HFR proxy defers
destruction by two ticks for its recorded streams. EFB-copy textures are
owned by the copy registry and use ids `TC_ID_BASE + slot`.

## 6. D3D12 backend

* Device on the default adapter (feature level 11_0), one direct queue, DXGI
  flip-model swap chain (`FLIP_DISCARD`, 3 buffers, tearing flag when
  supported so V-Sync off is really uncapped), HWND from `SDL_GetWindowWMInfo`.
  d3d12.dll / dxgi.dll / d3dcompiler_47.dll are loaded at runtime, so the exe
  starts (and falls back to GL) where they are missing.
* The game renders into an offscreen colour target (RGBA8, MSAA = setting) +
  D24S8 depth. Present = resolve/copy into the back buffer, so EFB copies,
  F1 capture and frame dumps do not depend on the swap chain.
* Root signature: b0 root CBV (draw consts), b1 root CBV (TEV consts), SRV
  table t0-t7, sampler table s0-s7.
* Descriptor heaps: a CPU-only SRV heap (one descriptor per texture) and a
  shader-visible ring that receives 8-SRV tables (copied only when the bound
  set changes); a shader-visible sampler heap with a cache of 8-sampler tables
  keyed by the per-stage sampler state.
* Upload ring (persistently mapped UPLOAD heap, fenced per frame) for
  vertices, quad rects and constant blocks; constant blocks are deduplicated
  by memcmp against the last upload. Texture uploads go through the same ring
  (or a dedicated buffer for big ones) with `CopyTextureRegion`.
* PSO cache: the whole pipeline key (blend enable/src/dst/op, depth
  func/write, cull, depth clip, topology class) fits in 16 bits, so the cache
  is a flat 65536-entry array.
* Quads and triangle fans use static index buffers (D3D12 has no fans);
  lines are already expanded to triangles by the core.
* Shaders: HLSL port of the GLSL, compiled at startup with `D3DCompile`
  (SM 5.1), because the mingw build has no fxc/dxc. The bytecode is cached
  in `<save dir>/d3d12_shader_cache.bin`, keyed by a hash of the source and
  compile options. Every HLSL function has a single exit (FXC miscompiles the
  TEV path with early returns), the TEV loop uses `SampleGrad` with
  derivatives taken before the loop (implicit-derivative sampling is not
  allowed in a dynamic loop), and arrays are read through constant-index
  selects (a dynamically indexed array goes to local memory).
* Depth is stored reversed (-z/w = 1 - GX depth; compare functions, clears
  and depth readback are flipped). The direct mapping z/w + 1 lies near 1.0
  for distant geometry, where float rounding in the VS and the interpolator
  is a D24 step or more: layers 1-2 steps apart (the 2-5 lava block shells)
  z-fought along their triangle edges (GL, with the same z/w mapping but
  its own rounding, shows only isolated pixels there).
* Rasterization: the VS nudges y by 1/256 pixel so edges on pixel centres
  fill the same row as GL (y-up); MSAA uses D3D's standard sample pattern.
* Mipmaps are generated on the CPU (2x2 box).
* Device removal is logged with the removed reason, then the game exits.

## 7. Selecting the renderer

* `--renderer gl|d3d12` (also `dx12`), else env `SMB2_RENDERER`, else
  `renderer=` in settings.dat, else `gl`.
* In game: F1 overlay or Options > Game Screen > "Renderer"
  (OpenGL / Direct3D 12, "(restart)" shown until the next launch).
* The window is created without `SDL_WINDOW_OPENGL` for D3D12. If D3D12
  cannot start (no d3d12.dll / dxgi / d3dcompiler_47, no FL 11_0 device, ...)
  the window is recreated for GL and the game runs on GL.
* Debug: `SMB2_D3D12_DEBUG=1` debug layer (+ info queue to stderr), `=2` adds
  GPU-based validation. Diagnostic switches: `SMB2_D3D12_FORCEFAIL`
  (exercise the GL fallback), `SMB2_D3D12_DEBUGVIS=n` (shader debug views),
  `SMB2_D3D12_NOCULL`, `SMB2_D3D12_NODEPTH`, `SMB2_D3D12_FLIPFACE`,
  `SMB2_D3D12_TRACECOPY`.

Parity between the backends is checked with frame dumps (`--dump-interval`)
compared by `tools/ppmtool diff` and `ppmtool sheet`. Deterministic frames
with MSAA off are identical or within 3/255; gameplay frames are not
deterministic run to run, so they are compared visually.

## 8. Known differences

* Mipmaps: the CPU box filter differs from glGenerateMipmap by a few levels
  on minified textures.
* MSAA edge coverage differs from GL (sample pattern).
* Depth EFB copies (`GXCopyTex` with a Z format) return 0 under MSAA on
  D3D12 (multisampled depth can't be resolved); the game uses no Z copy
  formats.
* D3D12 textures are committed resources (64 KB alignment each).
* Both backends: the batch still pending at present time is drawn into the
  next frame and cleared (GXEnd is a no-op, nothing flushes before the swap).
* `[d3d12] adapter ... MB` prints a truncated size in the 32-bit build.
